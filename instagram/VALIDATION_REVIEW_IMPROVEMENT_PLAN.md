# Validation review improvement plan

## Goal

Make project validation faster to review, less repetitive, and more reliable while preserving a complete audit trail.

## Principles

- Use current real production data first.
- Search historical production data before synthetic fallback or waiver.
- Keep synthetic contract-edge tests separate and non-publishable.
- Show each unique rendered result once in the summary review.
- Preserve every scenario and decision in the audit output and manifests.
- Fail automatically on measurable layout/rendering defects; reserve human review for design and factual judgement.

## Phase 1 — summary and audit review outputs

**Status: completed**

Implemented:

- `validation_contact_sheet.png` is a concise summary sheet
- the cover is shown once from a representative real example
- visual-shape scenarios show the visual slide only

Acceptance met:

- every required scenario is represented by a render group or waiver

## Phase 3 — historical real-data fallback

**Status: completed**

Implemented:

- adapter-specific historical S3 source discovery
- current production data searched first
- up to 12 recent historical production batches searched second
- batches ordered by S3 object modification time
- batch, item, source-key, and search-stage provenance recorded
- synthetic contract-edge data is not generated by convenience
- waiver occurs only after current and searched historical data fail
- every scenario records the four-stage decision path:
  - current real
  - historical real
  - synthetic contract edge
  - waiver

Live validation evidence:

- eight historical batches loaded
- zero current waivers replaced by the available history
- three scenarios remained waived
- successful run: `30871813098`

Acceptance met:

- every scenario manifest records search stages
- waivers state how many historical batches were checked
- no synthetic scenario is created for convenience
